# Top-100 adapter source audit

Reviewed September 4, 2026 against the working tree based on `e5918abb9830a88aee75d3be17bd0df3d2debccd`, including the pending AnyIO, gRPC and runner fixes. This is a source audit, not a claim that every package passed on every OS or that every possible upstream test lane is reproduced.

## Implementation follow-up

The approved source-audit fixes are implemented locally. **Hosted validation is
still required before publishing new compatibility claims.** No upstream build
or test code was executed locally, and no CI run, commit, push or deployment was
started.

Adapters remain in one alphabetically named file per package. All 100 now carry
their reviewed upstream `guidance` links. See the
[adapter guide](../src/willitjit/data/packages/README.md) for fields, recipe
overrides and the review process.

- **Runtime selection:** pytest and virtualenv now build/install using their
  upstream inputs and run directly in the survey environment, without nested
  tox. Both conditions have a logged post-install interpreter/SSL/toggle check.
- **Prerequisites:** restored AnyIO's hosts fixtures, urllib3's socket policy
  and FT extras, aiohttp's FT requirements, FastAPI's extras/docs path/FT
  SQLAlchemy setup, CFFI's Unix suite, and Arrow's wheel-test inputs.
- **Dependencies:** use the upstream inputs for Requests, idna,
  charset-normalizer, annotated-types, aiobotocore, Cryptography, Google auth,
  LiteLLM, Rich, aiohappyeyeballs and SoupSieve. Removed independent pytest,
  botocore, google-auth and pygments version workarounds. Rich's Poetry 1.3.1
  version is an explicit upstream CI pin, not a locally chosen downgrade.
- **Test semantics:** preserve Yarl/Uvicorn pytest configuration, remove the
  extra Pillow/multidict/pytest test exclusions and pydantic-settings warning
  suppression, restore upstream warning settings, and use Colorama's unittest
  runner. Include trove-classifiers' classifier validation and pytz's custom
  unittest/doctest suites. Remove jsonschema's unused pytest dependency.
- **Explicitly Not tested:** Protobuf and gRPC/grpcio-status still need a
  verified recipe for their generated tests and custom harnesses. Hugging Face
  needs a documented service-free lane; its broad exclusions and unrestricted
  retries are removed. tqdm needs a reviewed immutable replacement for its
  upstream mutable-Git nbval dependency. These five adapters now do no setup or
  test execution. BeautifulSoup remains untested because its source is not on GitHub.

The subsequent interpreter setup fix verified `test.support` and both runtime
toggles in all six hosted packaging jobs (run `33895535997`). Setuptools,
importlib-metadata and zipp now have restored upstream-based recipes, with
benchmark exclusions documented in their adapters. Their own targeted hosted
runs are still required; the historical missing-test.support findings below
describe the original environment.

Deliberate scope differences remain documented, not hidden: no coverage,
performance or credentialed integration jobs; serial execution; named
pure-Python, unit or installed-wheel lanes where upstream provides them.
Pillow remains enabled using the existing upstream image-fixture commit dated
2025-05-27, instead of moving main. s3fs uses its declared fsspec release range
rather than upstream CI's mutable Git main. The already-approved AnyIO test-only
upstream backport remains separately recorded in the adapter and result evidence.

New dependency inputs may expose genuine Python 3.14 or FT setup failures. Do
not reintroduce exclusions or arbitrary pins just to obtain green results.

Local validation passed: 76 core tests, API tests, frontend type checking,
Ruff, zizmor, and actionlint 1.7.12. These checks validate the harness and
configuration, not execution of the upstream package suites.

## How to read this

Every GitHub source link below is tied to the commit resolved from the adapter's selected release, not upstream main. All 100 registry entries were reviewed: 99 GitHub-hosted sources and the intentionally untested BeautifulSoup entry. Large Google monorepo tree listings were truncated; the common-protos component configuration was fetched directly instead of treating an absent listing as an absent file.

- **Aligned:** the runtime suite and dependency recipe have upstream support. Not an execution guarantee or a claim of identical CI.
- **Scoped:** a documented lane or explicit subset, with omitted variants noted.
- **Review:** the test runner/path is supported, but a local pin, environment adjustment, fixture setup or scope decision needs more evidence before signoff.
- **Fix:** a concrete mismatch that can affect the measurement, test coverage or execution safety.
- **Not tested:** no compatibility claim can be made.
- **Simplify:** an unnecessary departure from a simpler upstream command.

Coverage, linting, docs builds, credentialed services and performance jobs are not automatically requirements for this compatibility survey. In particular, do not copy benchmarks just because they are in upstream CI. Likewise, an upstream recipe that fetches mutable Git dependencies is not automatically acceptable under this project's security and reproducibility policy.

## Highest-priority findings

1. **The inner interpreter must be checked.** The pytest and virtualenv adapters launch tox. Their upstream pass-env lists do not include `PYTHON_JIT`, and their fixed environment names do not deliberately select FT. Current tox passes `PYTHON_GIL` by default, but not `PYTHON_JIT`; do not conflate those two settings. Our runner only verifies its outer interpreter and does not override tox's environment. Tox also runs its own commands, including coverage for virtualenv. An outer JIT toggle is not proof that the tests used that toggle. Select the exact inner interpreter, explicitly propagate the condition, and verify it inside the test environment. See the pinned tox configurations in rows 22 and 76 and [tox's default environment handling](https://github.com/tox-dev/tox/blob/main/src/tox/tox_env/api.py). This supporting tox reference is current main, not a package release pin; retain the installed tox version when validating the fix.
2. **Retries must not hide regressions.** Hugging Face's workflow limits retries with `--only-rerun`; our adapter drops that restriction. It also drops `--vcr-record=none`. Restore a deliberate failure policy and distinguish our offline exclusions from upstream's credentialed CI lane. See row 93.
3. **Restore upstream prerequisites.** AnyIO supplies DNS hosts fixtures; urllib3 restricts sockets and changes extras for FT; FastAPI uses `all`, a docs-source import path and FT-specific SQLAlchemy setup; aiohttp has FT-specific requirements. These are not interchangeable with the regular build's setup. See rows 5, 25, 49 and 63.
4. **Do not silently narrow suites.** Protobuf currently runs only three selected modules. CFFI applies a Windows shortcut to all OSes. LiteLLM and gRPC have globally applied exclusions with platform-specific rationales. Yarl and Uvicorn clear pytest options beyond parallelism. A passing result only describes the tests actually run. See rows 12, 33, 46, 50, 55 and 91.
5. **Prefer upstream dependency inputs.** Cryptography's CI constraints, Google auth's constraints, SoupSieve's parser requirements and Arrow's wheel-test requirements should take precedence over reconstructed lists. Existing local overrides, including google-auth, Click and pytest pins, need their own rationale and source link rather than being called upstream defaults.
